CIVICLENS — PHASE 1 DEVELOPMENT LOG Geospatial Civic Services &
Municipal Tax Intelligence Platform

Project Repository: civic-lens Phase: 1 — Foundation Goal: Establish the
basic full-stack application structure and verify that the React
frontend can communicate with the Express backend.

============================================================ PHASE 1
OVERVIEW ============================================================

Phase 1 focuses only on the application foundation.

Components introduced: 1. Git + GitHub 2. React + Vite frontend 3.
Node.js + Express backend 4. Backend middleware 5. REST health-check
endpoint 6. Axios API client 7. Frontend-to-backend communication 8. Git
ignore rules and first commit

We are deliberately NOT adding the database, authentication, GIS map,
tax modules, AI, or deployment today. Those belong to later phases.

============================================================ STEP 4 —
CREATE THE BACKEND
============================================================

Technology: Node.js + Express

Commands:

    cd ..
    mkdir backend
    cd backend
    npm init -y

Why Node.js? Node.js allows us to build the server-side application
using JavaScript, giving the project one primary programming language
across frontend and backend.

Why Express? Express is a lightweight Node.js framework for building
REST APIs, routing requests, and applying middleware.

Installed packages:

    npm install express cors dotenv helmet morgan bcryptjs jsonwebtoken pg

Development dependency:

    npm install -D nodemon

Why each package?

express Creates the HTTP server and REST API.

cors Allows the frontend and backend running on different local ports to
communicate during development.

dotenv Loads configuration and secrets from environment variables
instead of hard-coding them.

helmet Adds common HTTP security headers to improve the application’s
security baseline.

morgan Logs HTTP requests during development, making API debugging
easier.

bcryptjs Will be used later to securely hash user passwords.

jsonwebtoken Will be used later for JWT-based authentication.

pg PostgreSQL client for Node.js. It will be used when we add the
database in Phase 1/2 depending on the final setup.

nodemon Automatically restarts the backend when source files change
during development.

Status: [ ] Completed

============================================================ STEP 5 —
CREATE THE BACKEND STRUCTURE
============================================================

Initial structure:

    backend/
    ├── src/
    │   ├── config/
    │   ├── controllers/
    │   ├── middleware/
    │   ├── models/
    │   ├── routes/
    │   ├── services/
    │   └── app.js
    ├── .env
    ├── .env.example
    └── package.json

Why separate folders?

config Database and application configuration will live here.

controllers Handles request/response logic without putting everything
inside route files.

middleware Contains reusable request-processing logic such as
authentication and validation.

models Represents database-related data structures and operations.

routes Defines API endpoints and connects them to controllers.

services Contains business logic and external API integration.

app.js Main entry point where Express is configured.

Why organize early? A small project can work with everything in one
file, but CivicLens is intended to grow into a multi-feature
application. Early separation makes the code easier to maintain.

Status: [ ] Completed

============================================================ STEP 6 —
CREATE THE EXPRESS SERVER
============================================================

File:

    backend/src/app.js

Core setup:

    const express = require("express");
    const cors = require("cors");
    const helmet = require("helmet");
    const morgan = require("morgan");
    require("dotenv").config();

    const app = express();

Middleware used:

    app.use(cors());
    app.use(helmet());
    app.use(morgan("dev"));
    app.use(express.json());

Why middleware?

cors Allows requests from the React development server.

helmet Adds security-related HTTP headers.

morgan Displays incoming requests in the terminal for debugging.

express.json() Allows Express to read JSON request bodies.

dotenv Makes environment configuration available through process.env.

============================================================ STEP 9 —
CREATE THE FRONTEND API CLIENT
============================================================

File:

    frontend/src/services/api.js

Axios instance:

    import axios from "axios";

    const api = axios.create({
      baseURL: "http://localhost:5000/api",
      headers: {
        "Content-Type": "application/json",
      },
    });

    export default api;

Why create a shared Axios instance? Instead of writing the backend URL
repeatedly throughout the application, all API requests can use one
configured client.

For example:

    api.get("/health")

Later we can add: - authentication headers - interceptors - centralized
error handling - environment-based API URLs

This keeps API communication consistent across the frontend.

============================================================ STEP 11 —
CREATE .gitignore
============================================================

At the project root, create:

    .gitignore

Recommended entries:

    node_modules/
    .env
    dist/
    *.log
    .DS_Store

Why?

node_modules/ Dependencies can be recreated using package.json and
should not be committed.

.env Environment variables may contain passwords, API keys, or other
secrets.

dist/ Build output can be generated when needed.

*.log Temporary log files do not belong in source control.

.DS_Store macOS-generated metadata that is irrelevant to the project.

Security note: Never commit real passwords, database credentials, JWT
secrets, or API keys.
